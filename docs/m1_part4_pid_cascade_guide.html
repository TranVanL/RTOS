1. Mục tiêu và cách làm

Mục tiêu (plan M1 Phần 4): có bộ điều khiển PID cascade đủ an toàn để đưa lên node: không "windup", không giật khi đổi tham chiếu, đầu ra bị giới hạn (điện áp, tốc độ thay đổi điện áp, vị trí). Tất cả là hàm C không phụ thuộc OS, trạng thái truyền tường minh, để test trên host rồi dùng lại nguyên mã trên FreeRTOS (Phần 6).

Cách làm:

  1. Tách limits.c (clamp, rate limit) — hàm nhỏ nhất, test độc lập.
  2. Viết pid_step(): một vòng PID tổng quát (P + I + D) với anti-windup và saturation. Cấu hình bất biến (pid_params_t) tách khỏi trạng thái thay đổi (pid_state_t).
  3. Viết cascade_step() bằng cách ghép hai pid_step(): vòng ngoài vị trí → tốc độ đặt; vòng trong tốc độ → điện áp. Thêm kẹp tham chiếu vị trí và rate limit điện áp.
  4. Viết test_pid.c bám đúng 5 tiêu chí của plan, đưa vào CTest.

2. Kiến thức 1 — PID rời rạc

PID liên tục tính điều khiển \(u(t)\) từ sai số \(e(t)=r(t)-y(t)\) (tham chiếu trừ đo lường):

$$u(t)=K_p\,e(t)+K_i\int_0^t e(\tau)\,d\tau+K_d\,\frac{de}{dt}$$
  • P (tỉ lệ): phản ứng ngay với sai số hiện tại. Kp lớn → nhanh nhưng dễ dao động.
  • I (tích phân): cộng dồn sai số theo thời gian → triệt tiêu sai số xác lập (ví dụ khi có tải ngoài).
  • D (vi phân): phản ứng với tốc độ thay đổi → "giảm chấn", nhưng khuếch đại nhiễu.

Trên vi điều khiển, thời gian là rời rạc với bước cố định \(\Delta t\) (ở đây 1 ms). Tích phân Euler tiến:

$$I_{k+1}=I_k+K_i\,e_k\,\Delta t,\qquad u_k=K_p e_k+I_{k+1}+D_k$$

Trong code, integral lưu luôn phần tích phân đã nhân Ki (đơn vị của đầu ra), không lưu tích phân thô của e. Lý do: khi cần kẹp "ngưỡng anti-windup" ta kẹp thẳng theo đơn vị đầu ra (vôn), dễ hiểu và không phải chia cho Ki.

Vì sao dt nằm trong tham số? Core không tự đọc đồng hồ. Mọi thứ phụ thuộc thời gian đi vào qua tham số dt_s, nên chạy lại cùng chuỗi đầu vào luôn ra cùng kết quả (tất định) và test được bằng số tick, không bằng giây thật.

3. Kiến thức 2 — Windup và anti-windup

Bộ tích phân luôn cộng dồn khi còn sai số. Nếu đầu ra đã bão hòa (ví dụ đã ở +12 V) mà sai số còn dương, tích phân vẫn phình to dù đầu ra thực không tăng thêm. Khi tham chiếu đạt tới, bộ tích phân đã "no" quá mức nên phải xả bằng cách tạo sai số âm lâu → overshoot lớn và hồi phục chậm. Đây là integrator windup.

4. Kiến thức 3 — Đạo hàm trên đo lường và bộ lọc

Nếu lấy đạo hàm của sai số \(e=r-y\), khi tham chiếu \(r\) nhảy bậc, \(de/dt\) rất lớn trong một mẫu → đầu ra giật mạnh (derivative kick). Vì \(r\) thường là hằng số giữa hai lần đổi, \(\frac{de}{dt}=-\frac{dy}{dt}\) ngoài thời điểm nhảy, nên ta lấy thẳng đạo hàm của đo lường:

$$D_k=-K_d\,\frac{y_k-y_{k-1}{\Delta t}\ \text{(sau lọc thông thấp bậc 1: } d_f \leftarrow d_f+\alpha(d_{raw}-d_f)\text{)}$$

Lần gọi đầu tiên chưa có \(y_{k-1}\) nên has_prev=false và số hạng D bằng 0. Trong cascade hiện tại \(K_d=0\) (vòng tốc độ đã nhận tốc độ từ bộ ước lượng nên không cần thêm D), nhưng code D vẫn có và được test.

5. Kiến thức 4 — Cascade và đa tốc độ

Motor DC: điện áp → dòng/tốc độ → vị trí (tích phân của tốc độ). Điều khiển cascade chia thành hai vòng lồng nhau:

Vòng ngoài (vị trí)P: sai số vị trí → tốc độ đặt [rad/s]
Vòng trong (tốc độ)PI: sai số tốc độ → điện áp [V]
Plantmotor DC
  • Vòng trong phải nhanh hơn vòng ngoài khoảng 5–10 lần để từ góc nhìn vòng ngoài, vòng trong gần như "tức thời" — nhờ đó tuning được từng vòng riêng (tuning vòng trong trước).
  • Vòng ngoài chỉ cần P: vị trí là tích phân của tốc độ, nên vòng tốc độ + plant đã chứa một tích phân, sai số xác lập về vị trí sẽ bằng 0 mà không cần I ngoài.
  • Vòng trong dùng PI: I để triệt tiêu sai số tốc độ do tải.
  • Đa tốc độ: outer_divider = 5 nghĩa là vòng ngoài chạy mỗi 5 tick (200 Hz), vòng trong mỗi tick (1 kHz); tốc độ đặt được giữ giữa hai lần cập nhật.

7. Code đã viết

7.1 limits.c

float limits_clamp(float x, float lo, float hi)
{
    if (x != x) {
        return 0.0f;
    }
    if (lo > hi) {
        const float t = lo;
        lo = hi;
        hi = t;
    }
    if (x < lo) {
        return lo;
    }
    if (x > hi) {
        return hi;
    }
    return x;
}

common/control/limits.c

float limits_rate_limit(float prev, float target, float max_delta)
{
    if (target != target) {
        return prev;
    }
    if (max_delta <= 0.0f) {
        return target;
    }
    const float d = target - prev;
    if (d > max_delta) {
        return prev + max_delta;
    }
    if (d < -max_delta) {
        return prev - max_delta;
    }
    return target;
}

common/control/limits.c

Điểm cần chú ý: x != x là cách kiểm tra NaN không cần math.h; clamp tự hoán đổi nếu truyền nhầm lo > hi.

7.2 pid_step() — lõi PID

float pid_step(pid_state_t *s, const pid_params_t *p, float ref, float meas)
{
    if (s == NULL || p == NULL || !(p->dt_s > 0.0f) || !is_finite_f(ref) || !is_finite_f(meas)) {
        return 0.0f;
    }

    const float err = ref - meas;
    const float pterm = p->kp * err;

    float d_term = 0.0f;
    if (s->has_prev && p->kd != 0.0f) {
        const float raw = -(meas - s->prev_meas) / p->dt_s;
        const float a = (p->d_alpha > 0.0f && p->d_alpha <= 1.0f) ? p->d_alpha : 1.0f;
        s->d_filt += a * (raw - s->d_filt);
        d_term = p->kd * s->d_filt;
    }
    s->prev_meas = meas;
    s->has_prev = true;

    float integ = s->integral + p->ki * err * p->dt_s;
    if (p->integral_limit > 0.0f) {
        integ = limits_clamp(integ, -p->integral_limit, p->integral_limit);
    }

    const float u_unsat = pterm + integ + d_term;
    const float u = limits_clamp(u_unsat, p->out_min, p->out_max);
    const bool sat = (u != u_unsat);

    /* Conditional clamping: freeze integral if saturated and error pushes further. */
    const bool pushing = (u_unsat > p->out_max && err > 0.0f)
                      || (u_unsat < p->out_min && err < 0.0f);
    if (!(sat && pushing)) {
        s->integral = integ;
    }
    s->saturated = sat;
    return u;
}

common/control/pid.c

Đọc theo thứ tự: (1) kiểm tra đầu vào; (2) tính P; (3) tính D trên đo lường có lọc; (4) tính tích phân ứng viên và kẹp bằng integral_limit; (5) tính đầu ra chưa bão hòa → bão hòa; (6) chỉ commit tích phân mới nếu không rơi vào trường hợp "bão hòa và sai số đẩy tiếp".

7.3 cascade_step()

float cascade_step(cascade_state_t *s, const cascade_params_t *c,
                   float ref_pos, float pos, float vel)
{
    if (s == NULL || c == NULL || c->outer_divider == 0U
        || !is_finite_f(ref_pos) || !is_finite_f(pos) || !is_finite_f(vel)) {
        return 0.0f;
    }

    const float ref = limits_clamp(ref_pos, c->pos_min_rad, c->pos_max_rad);

    if ((s->tick % c->outer_divider) == 0U) {
        s->vel_setpoint = pid_step(&s->pos, &c->pos, ref, pos);
    }
    s->tick++;

    float v = pid_step(&s->vel, &c->vel, s->vel_setpoint, vel);
    v = limits_rate_limit(s->last_volt, v, c->volt_rate_v_per_tick);
    s->last_volt = v;
    return v;
}

7.4 Các kiểu dữ liệu (rút gọn từ pid.h)

typedef struct {
    float kp;
    float ki;               /* [1/s] scaling applied to the integral of error */
    float kd;
    float dt_s;             /* fixed step, > 0 */
    float out_min;          /* saturation */
    float out_max;
    float integral_limit;   /* |integral term| clamp (anti-windup threshold), >= 0; 0 = no limit */
    float d_alpha;          /* derivative low-pass in (0,1]; 1 = no filtering */
} pid_params_t;

typedef struct {
    float integral;         /* integral TERM (already multiplied by ki) */
    float prev_meas;
    float d_filt;
    bool  has_prev;         /* false until first step (avoids derivative kick) */
    bool  saturated;        /* last output was clamped */
} pid_state_t;

common/control/pid.h

Tên kiểu: không dùng pid_t vì POSIX đã dùng tên này cho process ID; dự án dùng pid_params_t, pid_state_t.

9. Quyết định thiết kế và lưu ý

  • Gain trong cascade_default_params ở thời điểm Phần 4 chỉ là nháp (Kp vị trí 20; PI tốc độ 0,5 / 5). Phần 5 sẽ đo rồi đổi — bộ gain nháp thực tế dao động (xem Phần 5).
  • Chưa có prefilter / giới hạn tốc độ tham chiếu cho bước thang; chỉ thêm nếu Phần 5 cho thấy overshoot vượt 10 %.
  • float mềm trên Cortex-M3 (không FPU): chi phí đo ở Phần 7, không đoán.
  • Vòng ngoài và trong dùng chung một kiểu pid_params_t/pid_step → ít mã hơn, ít chỗ để lỗi.
