1. Trạng thái dự án hiện tại

Milestone đang ở M0 (môi trường SIL + đường kết nối). Theo kế hoạch 7 milestone M0→M6, M0–M4 là mức tối thiểu để ghi CV.

Phần còn thiếu để đóng gate M0 nằm ở phía QNX (VM, license non-commercial, bridge mạng QNX VM ↔ QEMU), không phải code FreeRTOS. Toàn bộ phần FreeRTOS của M0 (MPU, watchdog, UDP, đo jitter) coi như xong và có bằng chứng.

2. Build system

freertos/CMakeLists.txt build target node.elf:

  • Tham số mạng NODE_IP/NODE_NETMASK/NODE_GATEWAY truyền qua -D..., default trong FreeRTOSConfig.h.
  • PERIPH_TEST=<none|wdt|wdt_kick|dwt|icount> chọn đúng 1 bài test ngoại vi compile kèm — cách dựng nhiều biến thể build để kiểm chứng từng ngoại vi riêng mà không tạo nhánh code khác.
  • freertos_third_party (OBJECT library, build với -w): kernel (tasks/list/queue/timers/event_groups/stream_buffer), port ARM_CM3_MPU (MPU wrapper v2: mpu_wrappers_v2_asm.c + mpu_wrappers_v2.c), heap_4, toàn bộ FreeRTOS+TCP + driver LAN9118.
  • node.elf chỉ gồm code tự viết (port/startup.c, port/syscall.c, app/*.c) build với -Wall -Wextra.
  • Link bằng port/mps2_m3.ld, -nostartfiles, --specs=nano.specs --specs=nosys.specs (newlib nano, syscalls tự viết).

Toolchain: cmake/arm-none-eabi.cmake — chỉ khai CMAKE_SYSTEM_NAME Generic, compiler arm-none-eabi-gcc, CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY (bắt buộc cho cross-compile bare-metal vì chưa có linker script lúc CMake tự kiểm tra compiler).

Lệnh build chuẩn: cmake --preset node && cmake --build --preset node (preset trong CMakePresets.json, build vào build/freertos).

3. Port layer — bare-metal (freertos/port/)

startup.c

  • Reset_Handler (naked, -O0 để tránh gcc thay bằng memcpy): set SP = _estack, copy .data flash→RAM, zero .bss, nhảy _start().
  • Default_Handler: đọc ICSR (0xE000ED04) để biết ngắt đang active rồi loop vô hạn — dùng khi debug ngắt lạ chưa gán vector.
  • NMI_Handler: khai weak alias tới Default_Handler — ứng dụng override được (xem periph_test.c).
  • HardFault_Handler, MemMang_Handler, BusFault_Handler, UsageFault_Handler, Debug_Handler: trampoline asm kiểm tra bit 2 của LR (EXC_RETURN) để biết dùng MSP hay PSP, nhảy tới hàm C xử lý.
    3 fault Bus/Usage/Debug đều trỏ chung vHandleMemoryFault — coi mọi fault "memory-ish" là một loại. HardFault_Handler hiện chỉ for(;;){} (debug qua gdb) — chưa ghi fault record + reset như REQ-SAF-007 yêu cầu cho control task thật. Đây là việc cần làm ở M1/M5.
  • isr_vector[]: mảng con trỏ đặt vào section .isr_vector. Index -5 (SVC) → vPortSVCHandler; -2/-1 (PendSV/SysTick) → xPortPendSVHandler/xPortSysTickHandler (từ FreeRTOS port, không phải code tự viết — đây là nơi context switch thật sự xảy ra); index 13 (Ethernet) → EthernetISR (driver LAN9118). Các slot 0 là ngắt chưa dùng.
  • _start(): uart_init() rồi main(), nếu return thì exit(0). exit/_exit dùng ARM semihosting (bkpt 0xab, SYS_EXIT) để QEMU thoát sạch khi chạy có -semihosting.

syscall.c (newlib stubs)

  • _write: ghi từng byte ra UART_DR (polling). Vì sao main.c gọi setvbuf(stdout, NULL, _IONBF, 0): _isatty() luôn trả 0 → newlib mặc định full-buffer stdout → log sẽ trễ/thiếu nếu không tắt buffering.
  • _read: luôn trả -1 (không có input).
  • _sbrk: cấp heap tuần tự cho malloc của C runtime — khác heap heap_4 của FreeRTOS (2 heap riêng biệt!). Giới hạn bởi _heap_top (linker script).
  • _fstat/_close/_lseek/_kill/_getpid: stub tối thiểu, không hành vi thật (bare-metal không có filesystem/process).
  • Có nhánh #ifdef __PICOLIBC__ khác (dùng FDEV_SETUP_STREAM) — project thủ sẵn 2 loại libc, hiện dùng nhánh newlib.

4. Linker script — MPU memory map (mps2_m3.ld)

File quyết định layout bộ nhớ mà portMPU_REGION_* trong code dựa vào.

FLASH (1 MB @ 0x0) ├─ .privileged_functions (64K đầu — chứa .isr_vector + code privileged) ├─ .text (code thường, có bảng syscall trampoline __syscalls_flash_*) ├─ .rodata, .ARM.extab, .ARM, .preinit/init/fini_array RAM (@ 0x20000000) ├─ .privileged_data (256K đầu, PHẢI là lũy thừa 2 — chứa ucHeap của heap_4 + biến PRIVILEGED_DATA) ├─ .data (biến thường, load từ FLASH) ├─ .tdata/.tbss (TLS, hiện không active vì PICOLIBC_TLS chưa bật) ├─ .bss (zero-init — CHỈ phần này bị Reset_Handler xoá) ├─ .noinit (NOLOAD) (KHÔNG load, KHÔNG bị zero → sống sót qua watchdog reset) ├─ ._user_heap_stack (heap_bottom/heap_top cho _sbrk + vùng stack cuối RAM)
  • __privileged_functions_region_size__ = 64K, __privileged_data_region_size__ = 256K — cố định tại link-time, không phải runtime. Vượt quá sẽ assert fail lúc build (ASSERT(__StackLimit >= _heap_top, ...)).
  • .noinit là lý do NoInit_t xNoInit trong periph_test.c giữ được boot_count/nmi_count qua nhiều lần watchdog reset.

  • ipconfigREPLY_TO_INCOMING_PINGS = 1, ipconfigSUPPORT_OUTGOING_PINGS = 0 — node trả lời ping, không tự ping.

6. Application layer — giải thích từng file

main.c

Entry point tối giản: app_net_init() → mpu_selftest_start() → periph_test_start() → vTaskStartScheduler(). udp_echo_start() không gọi trực tiếp ở đây mà từ network-up hook trong net.c.

net.c — network bring-up

void app_net_init( void )
{
    NVIC_SetPriority( ETHERNET_IRQn, configMAC_INTERRUPT_PRIORITY );
    pxMPS2_FillInterfaceDescriptor( 0, &xInterface );
    FreeRTOS_FillEndPoint( &xInterface, &xEndPoint, ucIPAddress, ucNetMask, ucGateway, ucDNSServer, ucMACAddress );
    configASSERT( FreeRTOS_IPInit_Multi() == pdTRUE );
}
  • 4 bước chuẩn của FreeRTOS+TCP multi-endpoint: set priority ngắt MAC → điền interface descriptor (driver LAN9118 cấp) → gắn IP/MAC tĩnh vào endpoint → IPInit_Multi().
  • NODE_IP_ADDR là macro dạng 10,0,2,15 không bọc ngoặc — cố ý, để expand đúng trong { } initializer list (nếu bọc ngoặc sẽ thành biểu thức dấu phẩy, sai).
  • vApplicationIPNetworkEventHook_Multi: cờ static xStarted đảm bảo udp_echo_start() chỉ chạy đúng 1 lần dù hook có thể được gọi lại nhiều lần khi mạng lên/xuống.
  • prvRand() (LCG, hằng số Numerical Recipes a=1664525,c=1013904223, seed cố định) cấp cho xApplicationGetRandomNumber/ulApplicationGetNextSequenceNumber — 2 hook bắt buộc của Plus-TCP (cổng nguồn UDP/ARP, TCP sequence number dù TCP đang tắt). Ghi rõ "Not cryptographic: SIL only".

hooks.c — callback bắt buộc của kernel/IP stack

  • vAssertCalled: taskENTER_CRITICAL() rồi loop vô hạn (biến volatile để compiler không tối ưu bỏ loop) — dừng tất định tại đúng điểm configASSERT fail để debug bằng gdb.
  • ulIdleCount + vApplicationIdleHook: tăng mỗi vòng idle task chạy — dùng làm proxy đo jitter ở periph_test.c (nhánh icount) vì QEMU không có DWT.
  • vApplicationStackOverflowHook: in tên task rồi dừng vô hạn — đáp ứng REQ-SAF-008 một phần, chưa ghi .noinit/reset (việc của M1/M5).
  • vApplicationGetIdleTaskMemory/vApplicationGetTimerTaskMemory: cấp bộ nhớ static cho idle/timer task — bắt buộc vì configSUPPORT_STATIC_ALLOCATION=1.
  • ulGetRunTimeCounterValue trả về 0 cố định — runtime-stats hiện không hoạt động thật, chỉ placeholder.

mpu_selftest.c — minh hoạ MPU 2-task + fault handler

static uint8_t ucProtected[32] __attribute__((aligned(32)));   // RO cho unprivileged
static volatile uint8_t ucExpected[32] __attribute__((aligned(32))); // cờ "fault cố ý"
  • aligned(REGION_SIZE) bắt buộc: MPU Cortex-M3 yêu cầu địa chỉ base chia hết cho kích thước vùng (power-of-2).
  • vHandleMemoryFault(pulFrame): pulFrame[6] = PC tại thời điểm fault (thứ tự exception stack frame chuẩn ARM: r0,r1,r2,r3,r12,lr,pc,xpsr). Đọc halfword đầu tại PC, kiểm tra 5 bit cao để biết lệnh Thumb 16-bit hay 32-bit Thumb-2 (≥ 0x1D là 32-bit) → cộng đúng độ dài lệnh vào PC để bỏ qua lệnh gây fault khi resume (nếu không làm bước này, fault sẽ lặp vô hạn).
  • SCB_CFSR = ulLastCFSR; — ghi lại đúng giá trị vừa đọc để xoá cờ theo cơ chế write-1-to-clear.
  • Nhánh else { for(;;){} }: fault không cố ý (ucExpected[0]!=1) → dừng vô hạn, không che giấu lỗi thật.
  • xTaskCreateRestricted với xRegions[]: ucProtected = PRIVILEGED_READ_WRITE_UNPRIV_READ_ONLY | EXECUTE_NEVER; ucExpected = READ_WRITE | EXECUTE_NEVER (cả 2 mức ghi được, vì chính task unprivileged cần ghi cờ báo trước).

udp_echo.c

1 task privileged (đụng socket/queue của TCP stack), bind NODE_UDP_PORT (5000), vòng lặp recvfrom→sendto, timeout SO_RCVTIMEO để in báo cáo rx/tx mỗi 5 s. Toàn bộ "ứng dụng" của M0 — sẽ là nền tảng đổi thành Comm task (parse frame + E2E) ở M1/M2.

7. Thiết kế mạng chi tiết

Tầng vật lý/driver

1 NIC LAN9118 mô phỏng (driver third-party smsc9220_eth_drv.c). net.c không viết driver, chỉ gọi pxMPS2_FillInterfaceDescriptor() để điền con trỏ hàm chuẩn (pfInitialise, pfOutput...) vào NetworkInterface_t.

Tầng IP — 1 endpoint tĩnh

Không DHCP (ipconfigUSE_DHCP=0) → khởi động tất định, không chờ discover/offer. IP/MAC lấy từ macro NODE_IP_ADDR/NODE_NETMASK/NODE_GATEWAY/NODE_MAC_ADDR (override được qua CMake).

Tầng transport — chỉ UDP

ipconfigUSE_TCP=0 tắt hoàn toàn TCP ở compile-time, đúng scope "CAN FD-compatible frame over UDP" của kiến trúc tổng.

Mạng QEMU ↔ host/QNX VM (tham số dòng lệnh, ngoài code)

  • QEMU dùng -netdev user,id=n0,hostfwd=udp::5000-:5000 -net nic,model=lan9118,netdev=n0 (SLIRP, không cần root).
  • Node thấy "host" ở 10.0.2.2 (gateway giả SLIRP).
  • Giới hạn quan trọng: SLIRP chỉ cho node đi ra host dễ dàng; chiều host → node cần hostfwd. Nếu node chủ động gửi tới 10.0.2.2, gói chỉ tới host, không tự động tới QNX VM — cần relay Python hoặc -netdev tap (cần root, chưa thử được trên máy hiện tại).

8. Việc tiếp theo (M1 — chưa bắt đầu)

Theo 02_PROJECT_PLAN.md mục M1 và 01_ARCHITECTURE.md §5.2:

  1. Plant + encoder model (C thuần, host-testable): motor DC bậc 2 (Euler/RK2, 1 ms), encoder lượng tử hoá + nhiễu Gaussian + cờ "stuck" (cho F8 sau này). File dự kiến: freertos/control/plant.c/h, encoder.c/h.
  2. PID cascade: vị trí → tốc độ, anti-windup, saturation, rate limit (REQ-FUN-001). File: freertos/control/pid.c/h.
  3. Control task 1 kHz (vTaskDelayUntil), MPU restricted — tái dùng pattern xTaskCreateRestricted từ mpu_selftest.c.
  4. Đo jitter bằng SysTick (không DWT — đã xác nhận không có model trong QEMU), đo trực tiếp thời điểm vào/ra control task thay vì idle-hook.
  5. Unit test host (Unity/Ceedling) cho PID/plant/encoder trong freertos/tests/ — chạy được trong CI, không cần QEMU.
Acceptance M1: step response overshoot < 10%, settling time theo tham số đã chọn, histogram jitter xuất được, unit test PID/plant pass trên host.
