1. Tóm tắt trước

Trong M0, project chưa truyền command điều khiển motor. Mục tiêu là kiểm tra đường mạng bằng hai kiểu echo độc lập: một gói do QNX phát, một gói do FreeRTOS phát.

Luồng 1 · port 5000

QNX phát → FreeRTOS echo → QNX kiểm tra. QNX đếm số gói gửi, số gói quay về và kiểm tra các từ dữ liệu có bị đổi không.

QNX chủ động gửi

Luồng 2 · port 5100

FreeRTOS probe → QNX echo → FreeRTOS nhận lại. QNX theo dõi sequence nhận được để ước lượng gói mất trên chiều node → QNX.

FreeRTOS chủ động gửi

Điểm cần nhớ: “hai chiều” ở đây là hai bài test riêng. Luồng 1 xác nhận round-trip bắt đầu từ QNX; luồng 2 xác nhận round-trip bắt đầu từ node. Ở cả hai, UDP không tự xác nhận hoặc truyền lại gói; code ứng dụng tự đếm và đánh giá.

IP address

Chỉ máy/endpoint nào đang nhận gói. Ví dụ node gửi đến IP peer QNX 192.168.50.1.

UDP port

Chỉ ứng dụng/socket nào trong máy đích nhận gói. Ví dụ port 5100 đưa gói tới socket probe/peer.

Socket

Endpoint mà code tạo bằng socket() hoặc FreeRTOS_socket(). Socket được bind port để nhận datagram.

Datagram

Một gói UDP độc lập. UDP không tạo kết nối như TCP, không đảm bảo giao hàng, thứ tự hay chống trùng.

Đừng nhầm hai port với nhau: 5000 dùng cho gói test do QNX gửi đến node. 5100 dùng cho probe do node gửi đến QNX và gói echo quay về. Cổng 5555 là đường socket backend của QEMU ở host, không phải UDP port trong packet ứng dụng.

Ở build nghiệm thu, macro CMake đặt IP node thành 192,168,50,2 và gateway thành 192,168,50,1. Header dùng gateway làm peer mặc định qua NODE_PEER_IP_ADDR. Với hai máy cùng subnet /24, việc gửi tới peer cùng subnet không cần router; ở cấu hình test, gateway cũng được dùng làm địa chỉ peer QNX.

Mã tích hợp mạng — app_net_init() và network-up hook

Nội dung dưới đây là phần liên quan từ freertos/app/net.c.

static const uint8_t ucIPAddress[ 4 ]  = { NODE_IP_ADDR };
static const uint8_t ucNetMask[ 4 ]    = { NODE_NETMASK };
static const uint8_t ucGateway[ 4 ]    = { NODE_GATEWAY };
static const uint8_t ucDNSServer[ 4 ]  = { NODE_GATEWAY };
static const uint8_t ucMACAddress[ 6 ] = { NODE_MAC_ADDR };

static NetworkInterface_t xInterface;
static NetworkEndPoint_t xEndPoint;

void app_net_init( void )
{
    NVIC_SetPriority( ETHERNET_IRQn, configMAC_INTERRUPT_PRIORITY );
    pxMPS2_FillInterfaceDescriptor( 0, &xInterface );
    FreeRTOS_FillEndPoint( &xInterface, &xEndPoint,
                           ucIPAddress, ucNetMask, ucGateway,
                           ucDNSServer, ucMACAddress );
    configASSERT( FreeRTOS_IPInit_Multi() == pdTRUE );
}

void vApplicationIPNetworkEventHook_Multi(
    eIPCallbackEvent_t eNetworkEvent,
    struct xNetworkEndPoint * pxEndPoint )
{
    static BaseType_t xStarted = pdFALSE;
    ( void ) pxEndPoint;

    if( ( eNetworkEvent == eNetworkUp ) && ( xStarted == pdFALSE ) )
    {
        xStarted = pdTRUE;
        printf( "network up, ip %u.%u.%u.%u\n",
                ucIPAddress[ 0 ], ucIPAddress[ 1 ],
                ucIPAddress[ 2 ], ucIPAddress[ 3 ] );
        udp_echo_start();
#ifdef NODE_PROBE
        udp_probe_start();
#endif
    }
}
  • xStarted ngăn việc tạo task lặp lại nếu hook nhận sự kiện mạng lên nhiều lần.
  • Task echo/probe chỉ bắt đầu khi interface đã sẵn sàng; không gửi ngay trong main().
  • FreeRTOS_FillEndPoint() nhận địa chỉ, netmask, gateway, DNS và MAC; ở đây địa chỉ được cấu hình tĩnh.
Macro port và địa chỉ — FreeRTOSConfig.h 
#define NODE_MAC_ADDR     0x52,0x54,0x00,0x12,0x34,0xAD
#define NODE_UDP_PORT     5000
#define NODE_PROBE_PORT   5100
#ifndef NODE_PEER_IP_ADDR
#define NODE_PEER_IP_ADDR NODE_GATEWAY
#endif

Địa chỉ node, netmask và gateway có giá trị fallback trong FreeRTOSConfig.h, nhưng CMake có thể override lúc build. Vì vậy địa chỉ chạy thực tế phải xác định từ cấu hình build, không chỉ nhìn giá trị fallback trong header.

5. Luồng 1 — giải thích code udp_echo

udp_echo.c là server UDP echo chạy trong task FreeRTOS. Nó không hiểu “sequence” hay cấu trúc payload của QNX; nhiệm vụ của nó là nhận một datagram rồi trả lại nguyên byte cho sender.

Khởi tạo socket

Socket_t xSock = FreeRTOS_socket(
    FREERTOS_AF_INET, FREERTOS_SOCK_DGRAM, FREERTOS_IPPROTO_UDP );
configASSERT( xSock != FREERTOS_INVALID_SOCKET );

memset( &xBind, 0, sizeof( xBind ) );
xBind.sin_family = FREERTOS_AF_INET;
xBind.sin_port = FreeRTOS_htons( NODE_UDP_PORT );
configASSERT( FreeRTOS_bind( xSock, &xBind, sizeof( xBind ) ) == 0 );
  1. FreeRTOS_socket(... SOCK_DGRAM ... UDP) tạo socket IPv4/UDP.
  2. sin_family chọn IPv4.
  3. FreeRTOS_htons() chuyển port 5000 sang network byte order.
  4. FreeRTOS_bind() gắn socket vào port local 5000. Địa chỉ bind để 0 nên socket nhận trên địa chỉ local của node.
  5. configASSERT làm firmware dừng ở assert nếu tạo/bind thất bại thay vì âm thầm chạy sai.

Nhận và gửi echo

xFromLen = sizeof( xFrom );
int32_t n = FreeRTOS_recvfrom(
    xSock, ucBuf, sizeof( ucBuf ), 0, &xFrom, &xFromLen );

if( n > 0 )
{
    ulRxCount++;
    if( FreeRTOS_sendto( xSock, ucBuf, ( size_t ) n,
                         0, &xFrom, xFromLen ) == n )
    {
        ulTxCount++;
    }
}
  • recvfrom() ghi payload vào ucBuf, trả số byte nhận trong n, đồng thời ghi địa chỉ và port của sender vào xFrom.
  • sendto() gửi đúng n byte về chính xFrom. Đó là lý do QNX nhận phản hồi tại socket gửi ban đầu dù node không biết socket QNX dùng port nguồn nào.
  • ulRxCount đếm datagram node nhận được; ulTxCount chỉ tăng khi gửi echo đủ số byte.
  • Socket đặt receive timeout 1 giây để task có thể thức dậy định kỳ và in thống kê mỗi 5 giây.
Ý nghĩa “echo nguyên văn”: udp_echo dùng cùng buffer vừa nhận làm dữ liệu gửi lại. Không giải mã, không sửa sequence, không thêm header. Việc kiểm tra payload được làm ở QNX.

6. Luồng 2 — giải thích code udp_probe

udp_probe.c là task client/server UDP nhỏ trên node: nó vừa gửi gói tới QNX, vừa lắng nghe gói QNX echo lại trên cùng socket cổng 5100.

Socket bind local và địa chỉ đích

xSock = FreeRTOS_socket(
    FREERTOS_AF_INET, FREERTOS_SOCK_DGRAM, FREERTOS_IPPROTO_UDP );

xBind.sin_family = FREERTOS_AF_INET;
xBind.sin_port = FreeRTOS_htons( NODE_PROBE_PORT );
FreeRTOS_bind( xSock, &xBind, sizeof( xBind ) );

xPeer.sin_family = FREERTOS_AF_INET;
xPeer.sin_port = FreeRTOS_htons( NODE_PROBE_PORT );
xPeer.sin_address.ulIP_IPv4 =
    FreeRTOS_inet_addr_quick( NODE_PEER_IP_ADDR );

Socket bind vào node:5100 để nhận echo. Địa chỉ đích lại là QNX:5100. Cùng một số port nhưng thuộc hai máy khác nhau; không có xung đột vì IP khác nhau.

Tạo payload và phát probe

memset( ulPkt, 0, sizeof( ulPkt ) );
ulPkt[ 0 ] = PROBE_MAGIC; /* 0x4D305052, chữ "M0PR" */
ulPkt[ 1 ] = ulSent;      /* sequence */

if( FreeRTOS_sendto( xSock, ulPkt, sizeof( ulPkt ), 0,
                     &xPeer, sizeof( xPeer ) )
     == ( int32_t ) sizeof( ulPkt ) )
{
    ulSent++;
}

ulPkt có 8 phần tử uint32_t, tức 32 byte. Mỗi lần gửi, word 0 là magic, word 1 là sequence, word 2–7 bằng 0. Sequence chỉ tăng khi sendto() báo đã gửi đủ cả datagram 32 byte; nếu send thất bại, số đó sẽ được thử lại ở vòng kế tiếp.

Đọc các gói echo đang chờ

for( ; ; )
{
    xFromLen = sizeof( xFrom );
    int32_t n = FreeRTOS_recvfrom(
        xSock, ulPkt, sizeof( ulPkt ), 0, &xFrom, &xFromLen );
    if( n <= 0 ) { break; }
    if( ulPkt[ 0 ] == PROBE_MAGIC ) { ulEcho++; }
}

Socket được đặt receive timeout bằng 0, tức lần đọc không chờ. Vòng lặp lấy hết các datagram hiện có; khi không còn gói, nó thoát để task tiếp tục báo cáo và chờ nhịp gửi tiếp theo. Node chỉ kiểm tra magic và tăng bộ đếm ulEcho; nó không so sequence với sequence kỳ vọng.

Nhịp chạy và thống kê

if( ( int32_t ) ( xTaskGetTickCount() - xNextReport ) >= 0 )
{
    xNextReport += pdMS_TO_TICKS( 5000 );
    printf( "udp_probe sent=%lu echoed=%lu\n",
            ( unsigned long ) ulSent,
            ( unsigned long ) ulEcho );
}
vTaskDelayUntil( &xWake, pdMS_TO_TICKS( 10 ) );

vTaskDelayUntil() lên lịch theo mốc tick định kỳ, mỗi 10 tick. Cấu hình M0 dùng tick 1 kHz, nên mục tiêu danh nghĩa là khoảng 100 probe/giây. Đây là nhịp của scheduler/QEMU, không phải cam kết thời gian thực trên phần cứng.

Bộ đếm trên node không phải tiêu chí mất gói chính. sent là số lần send thành công; echoed là số datagram nhận lại có magic đúng. Không có so sánh sequence nên muốn biết gói nào bị mất thì xem phép tính phía QNX.

7. QNX m0_peer — phần trung tâm của bài nghiệm thu

QNX process m0_peer tạo hai socket UDP: s1 cho round-trip luồng 1 (bind port nguồn tạm), s2 bind port 5100 cho luồng 2. Nó chờ cả hai socket bằng poll() để phục vụ hai luồng trong cùng vòng lặp.

Socket và địa chỉ node

  • udp_bind(0) tạo socket rồi bind port 0. Hệ điều hành chọn một port nguồn khả dụng cho QNX.
  • udp_bind(PROBE_PORT) bind socket thứ hai vào port 5100 để node gửi probe tới.
  • node chứa IP được truyền ở command line và port 5000 để QNX gửi test packet.
  • htons() làm cùng vai trò đổi byte order của port như FreeRTOS_htons() ở node.

Lịch gửi của QNX

Tham số rate_hz được đổi thành khoảng nghỉ period = 1 / rate_hz. Ở mỗi mốc đến hạn trước t_end, QNX dựng 8 word (32 byte): p[0] là sequence, các word còn lại dùng công thức pattern. Chỉ khi sendto() trả đủ 32 byte mới tăng sent.

for (int i = 0; i < PKT_WORDS; i++)
    p[i] = sent * 2654435761u + i;
p[0] = sent;

if (sendto(s1, p, sizeof p, 0,
           (struct sockaddr *)&node, sizeof node)
    == (ssize_t)sizeof p)
{
    sent++;
}

Hằng số 2654435761u tạo pattern khác nhau theo sequence và vị trí word. Việc đó giúp phát hiện payload bị sửa/cắt; không phải mã hoá hay checksum bảo mật.

Xử lý phản hồi luồng 1

if (pf[0].revents & POLLIN) {
    fl = sizeof from;
    ssize_t n = recvfrom(s1, p, sizeof p, 0,
                         (struct sockaddr *)&from, &fl);
    if (n == (ssize_t)sizeof p) {
        int ok = 1;
        for (int i = 1; i < PKT_WORDS; i++)
            if (p[i] != p[0] * 2654435761u + i)
                ok = 0;
        if (ok) recv1++;
        else bad++;
    } else if (n >= 0) {
        bad++;
    }
}

QNX nhận datagram trên socket s1. Nếu độ dài không đúng 32 byte, hoặc các word 1–7 không khớp pattern dựa trên word 0, nó tăng bad. Nếu hợp lệ, tăng recv1. Như vậy mismatch là biến bad in ra cuối chương trình.

Nhận probe và echo lại luồng 2

if (pf[1].revents & POLLIN) {
    fl = sizeof from;
    ssize_t n = recvfrom(s2, p, sizeof p, 0,
                         (struct sockaddr *)&from, &fl);
    if (n == (ssize_t)sizeof p && p[0] == PROBE_MAGIC) {
        if (!have2) { first2 = p[1]; have2 = 1; }
        last2 = p[1];
        recv2++;
        sendto(s2, p, sizeof p, 0,
               (struct sockaddr *)&from, fl);
    }
}

QNX chỉ chấp nhận gói có đúng kích thước và magic đúng. Nó ghi sequence đầu tiên vào first2, sequence mới nhất vào last2, tăng recv2, rồi echo nguyên datagram về đúng địa chỉ/port node ghi trong from. Ở đây QNX không kiểm tra các word 2–7 của probe.

Poll, báo cáo và thời gian drain

  • poll(pf, 2, ms) chờ một trong hai socket có dữ liệu, tối đa đến mốc sự kiện tiếp theo.
  • Mỗi 30 giây in số liệu tạm thời; đó chỉ là tiến độ, chưa phải kết quả cuối.
  • Sau thời lượng chạy chính, peer chờ thêm 2 giây (t_drain) để các datagram đang trên đường về kịp được nhận trước khi tính kết quả.

8. Payload thực tế và cách tính PASS/FAIL

LuồngKích thướcWord 0Word 1Phần còn lại
QNX → node → QNX8 × 32-bit = 32 bytesequencepattern theo sequence và chỉ số wordcác pattern tiếp theo; node echo nguyên gói
node → QNX → node8 × 32-bit = 32 bytemagic 0x4D305052sequenceđược zero-fill; QNX echo nguyên gói

Trong code test, đây là mảng uint32_t được gửi trực tiếp bằng UDP, không có serializer riêng. Hai môi trường chạy của M0 là little-endian, nhưng đây vẫn là format thử nghiệm nội bộ; không nên xem là wire protocol portable cho MCU khác hoặc thiết bị thật.

Các phép tính cuối ở QNX

uint32_t exp2 = have2 ? last2 - first2 + 1 : 0;
uint32_t lost1 = sent - recv1;
uint32_t lost2 = exp2 - recv2;

int pass = sent > 0 && lost1 == 0 && bad == 0
           && recv2 > 0 && lost2 == 0;
BiếnDiễn giải
sentSố datagram QNX gửi thành công trong luồng 1.
recv1Số echo luồng 1 về đủ kích thước và payload pattern đúng.
lost1 = sent - recv1Chênh lệch tổng số gửi và số echo hợp lệ.
badSố datagram luồng 1 có kích thước hoặc payload không đúng.
first2, last2Sequence probe đầu và cuối mà QNX quan sát được.
exp2Độ dài sequence span từ first tới last, gồm cả hai đầu.
lost2 = exp2 - recv2Ước lượng thiếu gói probe trong span sequence đã quan sát.

PASS cần có traffic ở cả hai luồng, luồng 1 không mất/không sai payload, và luồng 2 không thiếu sequence theo phép tính trên. Nếu thiếu probe ngay ở đầu hoặc cuối phần chạy, span first2…last2 không tính những sequence mà QNX chưa từng thấy; vì vậy cách tính này đo gap bên trong span đã quan sát, không đo chính xác mọi gói có thể đã bị mất ở biên.

9. Script chạy bài nghiệm thu và log

run_m0.sh thực hiện chuỗi thao tác chính:

  1. Dùng QNX SDK qcc biên dịch qnx/tests/m0_peer.c với -lsocket.
  2. Khởi động QNX VM và chờ SSH sẵn sàng.
  3. Cấu hình QNX NIC vtnet1 là 192.168.50.1/24, copy binary peer vào VM.
  4. Khởi động QEMU Cortex-M3 với node ELF và LAN9118; QEMU ARM kết nối socket backend của VM ở 127.0.0.1:5555.
  5. Chờ node khởi động, sau đó chạy peer với IP node, thời lượng và rate.
  6. Lưu stdout peer vào docs/results/m0_qnx_...result, UART FreeRTOS vào docs/results/m0_node_...uart.txt.

# Chạy QNX VM + node + peer: 600 giây, QNX gửi 100 gói/giây

Lệnh build được ghi trong hướng dẫn M0 của project. Script run_m0.sh cần QNX image, SDK và key SSH đã được thiết lập; script dùng sẵn ELF ở build/freertos_link/node.elf, không tự build firmware.

Đọc kết quả đã lưu

dir1 (QNX->node->QNX): sent=60000 received=60000 lost=0 mismatch=0
dir2 (node->QNX):      expected=60033 received=60033 lost=0
PASS

expected của luồng 2 có thể không trùng đúng sent luồng 1: node tự chạy probe theo tick FreeRTOS/QEMU, QNX gửi luồng 1 theo lịch monotonic của VM. Hai bộ đếm thuộc hai luồng và hai scheduler khác nhau.

Kết quả M0 lưu trong repo: 600 giây, 100 Hz, luồng QNX→node→QNX nhận đủ 60.000 gói, mismatch 0; probe node→QNX cũng kết thúc với không có gap trong sequence span được đo. Đây là kết quả SIL/QEMU, không phải benchmark Ethernet vật lý.

10. Giới hạn và các điểm cần phân biệt

  • Chưa có reliability của UDP: không retransmit, không ACK ở tầng UDP. Bài test quan sát số liệu để phát hiện mất gói.
  • Không phải protocol điều khiển cuối: chưa có CAN-FD-compatible frame, E2E CRC/counter, heartbeat ứng dụng, safety state machine hay lệnh motor trong hai file này.
  • Luồng 2 không kiểm sequence ở node: node chỉ tăng echoed nếu magic đúng; QNX tính gap theo sequence nhận phía QNX.
  • Phép đo gap đơn giản: last2 - first2 + 1 - recv2 giả định sequence tăng đều, không wrap trong lần chạy và không có duplicate/reorder làm sai bộ đếm. Nó không phải bộ phân tích protocol tổng quát.
  • Luồng 1 dùng bộ đếm tổng: QNX so tổng sent với số echo hợp lệ; đây không phải bảng theo dõi sequence đã nhận nên không mô tả chính xác duplicate hay reorder.
  • SIL: cả hai OS được mô phỏng bằng QEMU trên host. QEMU chuyển Ethernet frame qua socket backend TCP localhost; không có dây Ethernet vật lý trong bài chạy được mô tả.
  • Không suy ra hard real-time: nhịp 10 tick và số liệu thời gian phản ánh cấu hình mô phỏng, không chứng minh deadline trên phần cứng thật.
Định vị đúng tài liệu: kiến trúc tổng thể của project nói đến control/telemetry, E-stop port 5001, management và E2E ở các milestone sau. Nhưng code nghiệm thu M0 đang được giải thích ở đây chỉ mở socket UDP 5000 và 5100 cho echo/probe.

Toàn bộ udp_echo.c — FreeRTOS echo trên 5000

Nguồn: freertos/app/udp_echo.c

/* UDP echo on NODE_UDP_PORT: send every datagram back to its sender. Whole M0 application. */
#include <stdio.h>
#include <string.h>
#include "FreeRTOS.h"
#include "task.h"
#include "FreeRTOS_IP.h"
#include "FreeRTOS_Sockets.h"
#include "app.h"

static volatile uint32_t ulRxCount, ulTxCount;

static void prvUdpEchoTask( void * pvParameters )
{
    static uint8_t ucBuf[ 1472 ];
    struct freertos_sockaddr xBind, xFrom;
    socklen_t xFromLen;
    Socket_t xSock;
    TickType_t xNextReport = xTaskGetTickCount() + pdMS_TO_TICKS( 5000 );

    ( void ) pvParameters;
    xSock = FreeRTOS_socket( FREERTOS_AF_INET, FREERTOS_SOCK_DGRAM, FREERTOS_IPPROTO_UDP );
    configASSERT( xSock != FREERTOS_INVALID_SOCKET );
    memset( &xBind, 0, sizeof( xBind ) );
    xBind.sin_family = FREERTOS_AF_INET;
    xBind.sin_port = FreeRTOS_htons( NODE_UDP_PORT );
    configASSERT( FreeRTOS_bind( xSock, &xBind, sizeof( xBind ) ) == 0 );
    { TickType_t xTo = pdMS_TO_TICKS( 1000 ); FreeRTOS_setsockopt( xSock, 0, FREERTOS_SO_RCVTIMEO, &xTo, sizeof( xTo ) ); }
    printf( "udp_echo listening on %d\n", NODE_UDP_PORT );

    for( ; ; )
    {
        xFromLen = sizeof( xFrom );
        int32_t n = FreeRTOS_recvfrom( xSock, ucBuf, sizeof( ucBuf ), 0, &xFrom, &xFromLen );
        if( n > 0 )
        {
            ulRxCount++;
            if( FreeRTOS_sendto( xSock, ucBuf, ( size_t ) n, 0, &xFrom, xFromLen ) == n ) { ulTxCount++; }
        }
        if( ( int32_t ) ( xTaskGetTickCount() - xNextReport ) >= 0 )
        {
            xNextReport += pdMS_TO_TICKS( 5000 );
            printf( "udp_echo rx=%lu tx=%lu\n", ( unsigned long ) ulRxCount, ( unsigned long ) ulTxCount );
        }
    }
}

void udp_echo_start( void )
{
    /* Privileged: sockets, queues and network buffers live in the kernel heap. */
    xTaskCreate( prvUdpEchoTask, "udp_echo", configMINIMAL_STACK_SIZE * 2, NULL,
                 ( tskIDLE_PRIORITY + 2 ) | portPRIVILEGE_BIT, NULL );
}
Toàn bộ udp_probe.c — FreeRTOS gửi/nhận trên 5100

Nguồn: freertos/app/udp_probe.c

/* M0 direction node -> QNX: send numbered datagrams to PEER (QNX) on NODE_PROBE_PORT every 10 ticks;
 * the peer echoes them back. Node counts sent/echoed; the peer counts gaps in seq (its own PASS criterion). */
#include <stdio.h>
#include <string.h>
#include "FreeRTOS.h"
#include "task.h"
#include "FreeRTOS_IP.h"
#include "FreeRTOS_Sockets.h"
#include "app.h"

#define PROBE_MAGIC 0x4D305052UL /* "M0PR" */
#define prvQuick( ... ) FreeRTOS_inet_addr_quick( __VA_ARGS__ ) /* expands NODE_PEER_IP_ADDR (a,b,c,d) first */

static void prvProbeTask( void * pvParameters )
{
    struct freertos_sockaddr xPeer, xBind, xFrom;
    socklen_t xFromLen;
    uint32_t ulPkt[ 8 ], ulSent = 0, ulEcho = 0;
    TickType_t xWake = xTaskGetTickCount(), xNextReport = xWake + pdMS_TO_TICKS( 5000 );
    TickType_t xNoWait = 0;
    Socket_t xSock = FreeRTOS_socket( FREERTOS_AF_INET, FREERTOS_SOCK_DGRAM, FREERTOS_IPPROTO_UDP );

    ( void ) pvParameters;
    configASSERT( xSock != FREERTOS_INVALID_SOCKET );
    memset( &xBind, 0, sizeof( xBind ) );
    xBind.sin_family = FREERTOS_AF_INET;
    xBind.sin_port = FreeRTOS_htons( NODE_PROBE_PORT );
    configASSERT( FreeRTOS_bind( xSock, &xBind, sizeof( xBind ) ) == 0 );
    FreeRTOS_setsockopt( xSock, 0, FREERTOS_SO_RCVTIMEO, &xNoWait, sizeof( xNoWait ) );
    memset( &xPeer, 0, sizeof( xPeer ) );
    xPeer.sin_family = FREERTOS_AF_INET;
    xPeer.sin_port = FreeRTOS_htons( NODE_PROBE_PORT );
    xPeer.sin_address.ulIP_IPv4 = prvQuick( NODE_PEER_IP_ADDR );
    printf( "udp_probe -> peer port %d\n", NODE_PROBE_PORT );

    for( ; ; )
    {
        memset( ulPkt, 0, sizeof( ulPkt ) );
        ulPkt[ 0 ] = PROBE_MAGIC;
        ulPkt[ 1 ] = ulSent;
        if( FreeRTOS_sendto( xSock, ulPkt, sizeof( ulPkt ), 0, &xPeer, sizeof( xPeer ) ) == ( int32_t ) sizeof( ulPkt ) ) { ulSent++; }
        for( ; ; )
        {
            xFromLen = sizeof( xFrom );
            int32_t n = FreeRTOS_recvfrom( xSock, ulPkt, sizeof( ulPkt ), 0, &xFrom, &xFromLen );
            if( n <= 0 ) { break; }
            if( ulPkt[ 0 ] == PROBE_MAGIC ) { ulEcho++; }
        }
        if( ( int32_t ) ( xTaskGetTickCount() - xNextReport ) >= 0 )
        {
            xNextReport += pdMS_TO_TICKS( 5000 );
            printf( "udp_probe sent=%lu echoed=%lu\n", ( unsigned long ) ulSent, ( unsigned long ) ulEcho );
        }
        vTaskDelayUntil( &xWake, pdMS_TO_TICKS( 10 ) );
    }
}

void udp_probe_start( void )
{
    xTaskCreate( prvProbeTask, "udp_probe", configMINIMAL_STACK_SIZE * 2, NULL,
                 ( tskIDLE_PRIORITY + 2 ) | portPRIVILEGE_BIT, NULL );
}
Toàn bộ m0_peer.c — QNX xử lý cả hai luồng

Nguồn: qnx/tests/m0_peer.c

/* M0 acceptance peer (QNX process). Both directions over UDP against the FreeRTOS node:
 *   dir 1 (QNX -> node -> QNX): send numbered datagrams to node:5000 at --rate Hz, node echoes, count replies.
 *   dir 2 (node -> QNX -> node): node sends numbered probes to us on :5100; we echo them and count gaps in seq.
 * PASS iff dir1 lost==0 && mismatch==0 && dir2 lost==0 (counts, not milliseconds).
 * Build: qcc -Vgcc_ntox86_64 -o m0_peer m0_peer.c -lsocket       Usage: m0_peer <node_ip> <duration_s> <rate_hz> */
#include <arpa/inet.h>
#include <poll.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <time.h>
#include <unistd.h>

#define NODE_PORT 5000
#define PROBE_PORT 5100
#define PROBE_MAGIC 0x4D305052u
#define PKT_WORDS 8

static double now(void) { struct timespec t; clock_gettime(CLOCK_MONOTONIC, &t); return t.tv_sec + t.tv_nsec * 1e-9; }

static int udp_bind(int port)
{
    int s = socket(AF_INET, SOCK_DGRAM, 0);
    struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(port), .sin_addr.s_addr = INADDR_ANY };
    if (s < 0 || bind(s, (struct sockaddr *)&a, sizeof a) != 0) { perror("bind"); exit(2); }
    return s;
}

int main(int argc, char **argv)
{
    if (argc < 4) { fprintf(stderr, "usage: %s <node_ip> <duration_s> <rate_hz>\n", argv[0]); return 2; }
    struct sockaddr_in node = { .sin_family = AF_INET, .sin_port = htons(NODE_PORT) };
    if (inet_pton(AF_INET, argv[1], &node.sin_addr) != 1) { fprintf(stderr, "bad ip\n"); return 2; }
    double duration = atof(argv[2]), period = 1.0 / atof(argv[3]);

    int s1 = udp_bind(0), s2 = udp_bind(PROBE_PORT);
    struct pollfd pf[2] = { { s1, POLLIN, 0 }, { s2, POLLIN, 0 } };
    uint32_t sent = 0, recv1 = 0, bad = 0;
    uint32_t first2 = 0, last2 = 0, recv2 = 0; int have2 = 0;
    double t0 = now(), t_next = t0, t_end = t0 + duration, t_drain = t_end + 2.0, t_rep = t0 + 30;

    for (;;) {
        double t = now();
        if (t >= t_drain) break;
        if (t < t_end && t >= t_next) {
            uint32_t p[PKT_WORDS];
            for (int i = 0; i < PKT_WORDS; i++) p[i] = sent * 2654435761u + i;
            p[0] = sent;
            if (sendto(s1, p, sizeof p, 0, (struct sockaddr *)&node, sizeof node) == (ssize_t)sizeof p) sent++;
            t_next += period;
        }
        double wake = (t < t_end ? t_next : t_drain);
        int ms = (int)((wake - now()) * 1000.0); if (ms < 0) ms = 0;
        if (poll(pf, 2, ms) > 0) {
            uint32_t p[PKT_WORDS]; struct sockaddr_in from; socklen_t fl;
            if (pf[0].revents & POLLIN) {
                fl = sizeof from; ssize_t n = recvfrom(s1, p, sizeof p, 0, (struct sockaddr *)&from, &fl);
                if (n == (ssize_t)sizeof p) {
                    int ok = 1; for (int i = 1; i < PKT_WORDS; i++) if (p[i] != p[0] * 2654435761u + i) ok = 0;
                    if (ok) recv1++; else bad++;
                } else if (n >= 0) bad++;
            }
            if (pf[1].revents & POLLIN) {
                fl = sizeof from; ssize_t n = recvfrom(s2, p, sizeof p, 0, (struct sockaddr *)&from, &fl);
                if (n == (ssize_t)sizeof p && p[0] == PROBE_MAGIC) {
                    if (!have2) { first2 = p[1]; have2 = 1; }
                    last2 = p[1]; recv2++;
                    sendto(s2, p, sizeof p, 0, (struct sockaddr *)&from, fl);
                }
            }
        }
        if (now() >= t_rep) { t_rep += 30; printf("t=%.0fs dir1 sent=%u recv=%u | dir2 recv=%u\n", now() - t0, sent, recv1, recv2); fflush(stdout); }
    }
    uint32_t exp2 = have2 ? last2 - first2 + 1 : 0, lost1 = sent - recv1, lost2 = exp2 - recv2;
    printf("dir1 (QNX->node->QNX): sent=%u received=%u lost=%u mismatch=%u\n", sent, recv1, lost1, bad);
    printf("dir2 (node->QNX):      expected=%u received=%u lost=%u\n", exp2, recv2, lost2);
    int pass = sent > 0 && lost1 == 0 && bad == 0 && recv2 > 0 && lost2 == 0;
    printf("%s\n", pass ? "PASS" : "FAIL");
    return pass ? 0 : 1;
}
